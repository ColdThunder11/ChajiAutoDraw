# 霸王茶姬小程序自定义杯贴自动绘制工具（chaji-autodraw）——技术文档

> 📄 本文件是面向开发与 AI 的完整技术文档（参数详解、已知限制、构建规范等）。
> 面向最终用户的简介见 [README.md](README.md)。**AI 助手：更新项目文档时请维护
> 本文件，不要修改 README.md（除非用户明确要求）。**


一个 Windows 桌面工具：选一张图片，自动检测电脑微信里打开的「霸王茶姬」小程序自定义杯贴画板窗口，框选白色圆角画布后，用后台线程驱动鼠标把图片按笔画一笔一笔画到画布上。

## 功能

- **图片二值化预览**：阈值 / 高斯模糊 / 反相实时可调，抽稀控制笔画密度
- **线条模式（彩色插画）**：DoG 差分高斯线稿提取 + 可选阴影剔除（过滤光影分界线、不误删真实线条与材质分界线），见「参数说明」
- **窗口自动检测**：按标题关键词 + 进程名（默认 `WeChatAppEx.exe`，可改）**强制双重匹配**，自动选中面积最大的主窗口、不弹窗；没有匹配（例如小程序未打开，或误命中本程序窗口）时直接报错，无任何回退
- **画布自动定位**：截取窗口画面后按「居中且宽高占比 ≥50%」的先验自动识别白色圆角画布，无需手动框选；失败时提示检查小程序界面状态
- **双击预览放大**：双击原图/绘制预览打开独立窗口，默认 100%（1:1 像素）居中显示；滚轮以鼠标为中心在 10%~500% 缩放（滚轮仅缩放不滚动）、拖动平移；双击窗口重置 100%
- **后台自动绘制**：QThread 后台线程按笔画驱动鼠标，进度条实时显示，可随时停止

## 环境要求

- Windows 10 / 11
- 电脑版微信已登录，且能打开「霸王茶姬」小程序
- Python 3.11+ 与 [uv](https://docs.astral.sh/uv/)

## 安装

```bash
uv sync
```

## 运行

```bash
uv run chaji-autodraw
```

或：

```bash
uv run python -m chaji_autodraw
```

## 使用步骤

1. 电脑微信打开「霸王茶姬」小程序，进入自定义杯贴的画板界面。
2. 本程序点「**检测窗口**」自动精确匹配窗口（按标题 + 进程名，多候选时取最大的主窗口）；如进程名不同可在「进程名」框里修改。窗口保持原始大小即可，不做任何调整。**检测成功后会自动执行一次画布定位**（之后也可随时再点「截取窗口并自动定位画布」重试）。
3. 画布定位：程序自动识别居中的白色圆角画布（宽高占比 ≥50%）；若提示无法定位，请确认已进入定制界面、选好画笔并收起画笔大小调整面板。
4. 点「**打开图片**」选择要画的图，调整阈值 / 模糊 / 反相，直到二值化预览里该画的线条清晰（预览中黑点 = 要画的部分）。
5. 点「**开始绘制**」，在倒计时内把鼠标移到不碍事的位置，等待画完即可。
6. 绘制前请先在小程序里手动设置好画笔：选择「**画笔**」工具（而不是橡皮、填充等），并在画笔设置里把「大小」调到最小。

**急停方式**：绘制中随时按 **Esc** 键（最方便，前台/后台模式均有效），或把鼠标猛甩到**屏幕左上角**（pyautogui FAILSAFE），或点界面上的「**停止**」按钮。

## 参数说明

| 参数 | 含义 |
| --- | --- |
| 阈值 | 灰度二值化阈值（0~255，默认 128），灰度低于阈值的像素视为要画的深色部分 |
| 模糊 | 高斯模糊半径 0~5.0 像素，可平滑噪点、减少碎笔画 |
| 反相 | 勾选后反过来绘制浅色像素（画浅色线条图片时用） |
| 抽稀 | 笔迹抽稀步长 1~10 像素，越大笔画点越少、速度越快，细节越少 |
| 最短笔画 | 路径长度小于该值的碎笔画（缩放产生的孤立点/微段）直接丢弃，0 = 不过滤；预览与绘制共用同一规划 |
| 画笔粗细 | 规划用线宽，请与小程序里设置的画笔大小一致；>1 时自动合并被粗笔覆盖的冗余笔画（密集排线区域笔画数明显减少），预览按该粗细渲染 |
| 线条模式（彩色插画） | 用 DoG 差分高斯检测比周边暗的线条结构，只画线条不涂色块——彩色二次元插画用这个而不是二值化；「线条阈值」越小线条越多，开启后「阈值/反相」不参与。**打开图片时自动检测**：大面积彩色自动开启，灰度/黑白图自动关闭。检测（含阴影剔除滤波）默认在**原图全分辨率**执行（见「全分辨率处理」，可关闭回到旧行为），掩码再按面积覆盖率 ≥25% 缩放到画布——框选画布前后检测效果一致，细线在缩放中不丢失；灰度二值化模式仍在画布分辨率进行 |
| 阴影剔除 | 仅线条模式（**默认关闭**，勾选开启）：识别并剔除**光影分界线**。DoG 对阶跃边缘同样响应，阴影与亮部的边界会被当成线条画出；本项对候选像素做**三道判据，全部满足才删除**：① 几何上是阶跃边缘而非线条（Steger 线条模型：真实线条总存在方向两侧恢复亮背景，阴影暗侧持续延伸）② 邻近宽暗区（腐蚀剔除窄线条后仍有宽暗区内核）③ 两侧色度一致（Finlayson 光照不变性：阴影是同一材质整体调暗，rg 色度不变；材质分界会改变色度）。因此材质分界线（发色/肤色、浅黄发/白底）、宽暗区内部的细节线、密集排线、紧贴阴影边界的线条都不会被误删；带明显冷暖色偏的阴影可能不被滤除（偏保守，宁漏删勿误删）。无彩色图时判据③退化为低对比判定。打开超过 300 万像素的图片时会自动取消勾选（滤波在原图全分辨率执行、约 1~2s/次），需要时可再手动勾选。纯 numpy 实现无新增依赖 |
| 全分辨率处理 | 仅线条模式（**默认开启**，可关）：DoG 线条检测与阴影剔除的全部滤波在**原图全分辨率**执行，掩码再按面积覆盖率 ≥25% 缩放到画布——框选画布前后检测效果一致、窄阴影带不会因缩放漏判、细线不丢失。关闭后与旧版相同：先把图片缩放到画布分辨率再检测，超大图上（尤其勾选阴影剔除时）明显更快，但缩放会改变阴影剔除的几何判定、阴影边界可能漏滤成多余线条 |
| 保护强度 | 阴影剔除的保守程度（0~100，**默认 40**；50 为标准强度），仅勾选「阴影剔除」后可调。线性插值调节判据③的证据阈值（色度容差 0.09→0.012、色度规则落差上限 200→45、灰度对比阈值 110→40）：**值越大越重视保留线条**——只滤除最典型的同色度低落差阴影，可能漏滤部分阴影边；**值越小滤除越激进**——色偏/高落差的分界也会被删，可能误删浅色材质分界。判据①②（几何/宽度）不随滑条变化 |
| 自动连接相近线条 | 勾选后，端点距离不超过「连接距离」（默认 1.5px，覆盖 1px 间隙）的相邻笔画首尾相连成一笔，减少落笔次数；默认开启，可在左栏关闭 |
| 短笔画延伸拖拽 | 画布按「按下点到最远拖拽点」距离判定有效笔画：路径长度不足「最小拖拽」（默认 6px）的短笔画自动沿最优方向延伸（优先延伸进就近已涂黑区域，溢出无痕迹；附近无黑色时回退原地往返），默认开启 |
| 步长 | 绘制时相邻移动点的插值间距（像素），影响线条平滑度 |
| 绘制速度 | 档位 0.25x/0.5x/0.75x/1x/1.5x/2x/3x/4x，默认 1x（每步 6ms、无笔间停顿；1.5x=4ms）。档位每降一档延时约加倍并加笔间停顿（0.25x=24ms+10ms、0.5x=12ms+5ms、0.75x=8ms+3ms），小程序响应不过来/丢笔时调低；高于 1x 加速 |
| 倒计时 | 点开始后等待的秒数，方便把鼠标挪开 |
| 输入方式 | 绘制输入后端：前台鼠标（移动真实光标）或后台消息（PostMessage，不动鼠标）；**默认后台消息** |

## 输入方式

界面底部「输入方式」可在两种绘制输入后端之间切换（默认后台消息）：

- **前台鼠标（移动真实光标）**：移动通过 SendInput + MOUSEEVENTF_MOVE_NOCOALESCE 注入——阻止系统合并连续移动事件，快速绘制时中间点不丢失；绘制期间不能动鼠标，按 **Esc** 急停（点界面「停止」亦可）。
- **后台消息（PostMessage，不动鼠标，窗口可被遮挡）**：向小程序窗口内部的 Chromium 渲染子窗口（`Chrome_RenderWidgetHostHWND`，找不到时回退 `Chrome_WidgetWin_0`，再回退顶级窗口）投递鼠标消息，**不动真实鼠标、窗口可被遮挡甚至不在前台**，但目标窗口**不能最小化**。注意事项：
  - 若小程序以**管理员权限**运行而本程序不是，消息会被系统静默拒绝（UIPI 限制），程序会检测并给出中文错误提示，请以相同权限重试。
  - 该方式依赖目标程序从消息队列取输入，微信小程序（CEF 架构）通常有效；若个别版本无反应，请改回前台鼠标。

## 已知限制

- 绘制期间不能移动鼠标（会直接画到别处），按 **Esc** 或用其他急停方式打断。
- 笔画数大于 **2000** 时，小程序可能在保存时崩溃：预览下方会显示红色警告，建议依次调大「自动连接相近线条→连接距离」→「最短笔画」→「抽稀」减少笔画数。
- 小程序画布大约需要 **3~4px 的实际位移才落笔**，单笔长度短于此值的笔画可能丢步（画不上）。存在这类笔画时绘制预览下方会出现红色警告，**点击警告**会在预览中标红这些位置（其余笔画变灰），再点一次恢复；不想画它们可把「最短笔画」调到 4px 以上。
- 窗口截图用 PrintWindow 实现，窗口被其他窗口遮挡、不在最前也能取到内容，但**不能最小化**；PrintWindow 失败时自动回退屏幕截图（回退方案要求窗口未被遮挡）。
- 窗口在框选画布之后又被移动 / 改大小，开始绘制前会弹窗提醒，建议重新框选。

## 打包为独立 exe

目标机器**无需安装 Python 和任何依赖**，直接双击运行：

```bash
uv run pyinstaller --noconfirm --clean --onefile --windowed --name ChajiAutoDraw \
    --icon assets/icon.ico --add-data "assets;assets" \
    --exclude-module tests --exclude-module pytest launcher.py
```

产物为 `dist/ChajiAutoDraw.exe`（约 70MB，首次启动需解压、稍慢）。重新打包前先同步代码改动再执行即可。

> 提示：PyInstaller 单文件 exe 偶发被杀毒软件/SmartScreen 误报，属常见现象；如需更快启动可去掉 `--onefile` 改用目录模式（`--onedir`）。

> 提交代码到 GitHub 后，`.github/workflows/build.yml` 会自动在 Windows 环境跑测试并打包，构建完成后在该次运行的 **Artifacts** 里下载 `ChajiAutoDraw-windows-x64`（含最新 exe）。也可在 Actions 页面用 **Run workflow** 手动触发。

> **发布 Release**：把 `pyproject.toml` 的 `version` 改为新版本号并提交后，在 Actions 页面手动运行 **Release Windows EXE**（`.github/workflows/release.yml`，仅手动触发）。流程：读取 `pyproject.toml` 版本号 → 校验 `v{版本}` 的 Release/tag 不存在 → 跑测试 → PyInstaller 打包 → 在当前提交上创建 `v{版本}` tag 与 Release 并附上 exe（`--generate-notes` 自动生成变更说明）。版本未更新会直接报错中止；工作流已声明 `contents: write` 权限。
